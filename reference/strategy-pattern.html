Strategy Pattern

A family of algorithms, each in its own object (or function), interchangeable at runtime. The context delegates; the client chooses.

Parts

RoleJobIn the bank
Strategy Shared interface for one algorithm InterestStrategy.calculate(balance)
Concrete strategy One variant of that algorithm FixedRate, PromotionalRate
Context Holds a strategy and delegates work SavingsAccount.add_interest()
Client Picks and (optionally) swaps the strategy Factory payload, CLI, promo job

When to reach for it

  • Same job, several ways to do it (interest, fees, routing, sorting).
  • You need to swap at runtime — not only at class-definition time.
  • A growing if/elif on “mode” or “type” inside one method.
  • Subclasses that differ only in one algorithm (inheritance explosion).

Python shapes (pick the smallest that fits)

# 1. Stateless: a function is a strategy
def fixed_rate(balance: float, rate: float = 0.02) -> float:
    return balance * rate

account.interest_fn = fixed_rate

# 2. Stateful: a callable object
class PromotionalRate:
    def __init__(self, rate: float, boost: float):
        self.rate, self.boost = rate, boost
    def __call__(self, balance: float) -> float:
        return balance * self.rate + self.boost

# 3. Contract-heavy: ABC (teams, plugins, interviews)
class InterestStrategy(ABC):
    @abstractmethod
    def calculate(self, balance: float) -> float: ...

Not the same as

PatternIntent
Factory Create the right object. Strategy: pick the right algorithm.
Template Method Vary a step via inheritance (static). Strategy varies via composition (runtime).
State Strategies are independent. States may know each other and switch the context.
Notifier (DIP) Same structure (inject + delegate). Strategy names the algorithm family.
