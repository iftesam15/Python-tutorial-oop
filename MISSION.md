# Mission: Object-Oriented Programming in Python

## Why
Preparing for software jobs/internships. Needs to go from "writes Python scripts with functions" to "designs Python systems with classes" — both to build a portfolio of OOP projects and to be able to reason about and discuss OOP design (including SOLID principles and common patterns) in interviews.

## Success looks like
- Can look at a real-world problem and model it as a class hierarchy, choosing between inheritance and composition deliberately (not by default).
- Uses Python-idiomatic OOP — properties, dunder methods, `@classmethod`/`@staticmethod`, ABCs — not just Java-style classes translated into Python.
- Can explain and apply SOLID principles and point to at least 2-3 common design patterns (Factory, Strategy, Observer) in their own code.
- Has a growing portfolio of daily projects of increasing difficulty, culminating in one multi-class capstone system worth showing in an interview or on GitHub.
- Can talk through the *why* behind a design decision out loud — the kind of thing that comes up in a technical interview.

## Constraints
- ~1-2 hours per day, daily cadence — one project per day, difficulty ramps slowly.
- Already comfortable writing Python (functions, loops, scripts) — starting from zero on classes/objects specifically.
- No hard deadline, but the job-prep framing means interview-relevant topics (SOLID, design patterns, being able to explain trade-offs) should be woven in, not skipped as "advanced/optional."
- No strong preference on project theme (CLI/games/backend-ish) — free to pick whatever best teaches the day's concept, but should stay portfolio-plausible (would not embarrass them in a GitHub repo or interview).

## Out of scope
- Web frameworks (Django/Flask specifics) — OOP concepts only, not framework idioms.
- GUI frameworks.
- Deep metaclass/descriptor internals — revisit only if it comes up naturally later.
- Concurrency/async patterns.
