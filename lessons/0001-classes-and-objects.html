Classes & Objects: Your First Blueprint

Today you stop writing scripts and start designing things that hold their own data. This is the single idea everything else in this path builds on.

The core idea

Every script you've written so far probably passed data into functions and got a result back out. A class flips that: it bundles data and the functions that act on that data into one unit, called an object. The class is the blueprint; each object you create from it is an instance — its own copy of the data, sharing the same behavior.

Concretely: a BankAccount class describes what every bank account looks like (it has an owner, a balance, a way to deposit and withdraw). Each actual account — yours, your friend's — is a separate instance with its own balance, built from that same blueprint.

Why this matters for interviews
This is the exact vocabulary interviewers use — "class," "instance," "attribute," "method." Getting the words precise now saves confusion later when the concepts get harder.

Anatomy of a class

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        self.balance -= amount


alice_account = BankAccount("Alice", 100)
bob_account = BankAccount("Bob")

alice_account.deposit(50)
print(alice_account.balance)   # 150
print(bob_account.balance)     # 0 — separate instance, separate data

Four things to notice:

  • class BankAccount: defines the blueprint. Nothing runs yet — no object exists.
  • __init__ is a special method Python calls automatically the moment you create an object (BankAccount("Alice", 100)). Its job is to set up the instance's starting data.
  • self is how a method refers to "this particular instance." self.balance inside deposit means "the balance belonging to whichever object called this method" — that's why alice_account.balance and bob_account.balance don't interfere with each other.
  • An attribute (self.owner, self.balance) is data stored on the object. A method (deposit, withdraw) is a function stored on the object, always taking self as its first parameter.

Today's project

Build: BankAccount v1

This is the first version of a system you'll keep extending on later days — inheritance, custom exceptions, design patterns will all attach to this same project. Get the fundamentals solid now.

Requirements:

  • A BankAccount class with __init__(self, owner, balance=0)
  • A deposit(self, amount) method that increases the balance
  • A withdraw(self, amount) method that decreases the balance, but refuses (print a message, don't withdraw) if the amount exceeds the balance
  • Create at least two separate accounts and prove — by printing balances — that they don't share data

Stretch goal (only if the above feels easy): add a transfer(self, other_account, amount) method that withdraws from one account and deposits into another.
