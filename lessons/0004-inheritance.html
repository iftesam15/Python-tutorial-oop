Inheritance: Reuse What Already Works

A real bank doesn't have one account type — it has savings accounts, checking accounts, each with their own extra rules, but all sharing the same core deposit/withdraw/balance behavior you already built and validated. Today you stop copy-pasting that behavior and start reusing it.

The core idea

A subclass — class SavingsAccount(BankAccount): — starts with everything the parent class (BankAccount) already has: every attribute, every method, including the validated balance/owner properties from yesterday. This is an is-a relationship: a SavingsAccount is a BankAccount, plus a bit extra. You only write the extra part.

super().__init__(...) is how a subclass calls its parent's constructor instead of duplicating it. Skipping it and rewriting self.owner = owner etc. yourself would work today, but it means every future fix to BankAccount.__init__ — a new validation rule, say — silently stops applying to your subclasses. super() keeps the reuse real, not just copied text that happens to look the same right now.

Anatomy: two subclasses

class SavingsAccount(BankAccount):
    def __init__(self, owner, balance=0, interest_rate=0.02):
        super().__init__(owner, balance)   # reuse the parent's setup
        self.interest_rate = interest_rate  # then add what's new

    def add_interest(self):
        interest = self.balance * self.interest_rate
        self.deposit(interest)              # reuses the inherited deposit()
        print(f"Added {interest:.2f} interest")


class CheckingAccount(BankAccount):
    def __init__(self, owner, balance=0, transaction_fee=1.5):
        super().__init__(owner, balance)
        self.transaction_fee = transaction_fee

    def withdraw_with_fee(self, amount):
        self.withdraw(amount + self.transaction_fee)  # reuses inherited withdraw()


savings = SavingsAccount("Dhrubo", 1000, interest_rate=0.05)
savings.add_interest()
print(savings.balance)                      # 1050.0 — deposit() still validates as before

checking = CheckingAccount("Jack", 500)
checking.withdraw_with_fee(100)
print(checking.balance)                     # 398.5

print(isinstance(savings, BankAccount))     # True — is-a relationship
print(isinstance(savings, CheckingAccount)) # False — siblings, not related to each other

Notice deposit and withdraw don't appear anywhere in either subclass — they're inherited untouched, balance validation included. That's the entire point: three days of work on BankAccount didn't get thrown away, it got reused.

A preview, not today's job
You might notice CheckingAccount can't actually go negative even with a "transaction fee" concept, because the balance setter from Day 3 still forbids it. Making a subclass genuinely change a parent's behavior (like allowing controlled overdraft) is method overriding — that's tomorrow's topic, polymorphism. Today is only about adding new behavior, not changing existing behavior.
