Operator Overloading: Custom Math & Comparison Logic

Why write wallet1.add(wallet2) or risk adding raw numbers without currency checking when you can write m1 + m2? Today you build a dedicated Money value object that overloads arithmetic and comparison operators safely.

The core idea

Operator Overloading lets your custom classes hook into Python's built-in operators like +, -, ==, and <. When Python sees a + b, it automatically invokes a.__add__(b) under the hood.

By defining these magic methods on value objects (like monetary amounts, vectors, or measurements), you make custom domain objects behave as naturally as built-in numbers while maintaining strict domain validation—such as refusing to add USD to EUR without conversion!

Operator SyntaxDunder MethodPurpose
a + b__add__(self, other)Addition of two objects
a - b__sub__(self, other)Subtraction of two objects
a == b__eq__(self, other)Equality comparison
a < b__lt__(self, other)Less-than comparison

Anatomy: a Money value object

class Money:
    def __init__(self, amount, currency="USD"):
        self.amount = float(amount)
        self.currency = currency.upper()

    def __repr__(self):
        return f"Money({self.amount!r}, {self.currency!r})"

    def __str__(self):
        return f"${self.amount:.2f} {self.currency}"

    def __add__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        if self.currency != other.currency:
            raise ValueError(f"Cannot add {self.currency} and {other.currency}")
        return Money(self.amount + other.amount, self.currency)

    def __sub__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        if self.currency != other.currency:
            raise ValueError(f"Cannot subtract {self.currency} and {other.currency}")
        return Money(self.amount - other.amount, self.currency)

    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return self.amount == other.amount and self.currency == other.currency

    def __lt__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        if self.currency != other.currency:
            raise ValueError(f"Cannot compare {self.currency} and {other.currency}")
        return self.amount < other.amount


m1 = Money(100, "USD")
m2 = Money(50, "USD")
m3 = Money(50, "EUR")

print(m1 + m2)        # $150.00 USD
print(m1 > m2)        # True
# print(m1 + m3)      # Raises ValueError: Cannot add USD and EUR
Immutability of Value Objects
Notice that __add__ returns a new Money instance rather than modifying self.amount directly. Value objects like money, coordinates, or dates should generally be immutable—calculating a sum produces a new value without side effects.
Guarding against invalid types
Always check isinstance(other, Money) first. If other is not a Money object (e.g. m1 + 50), returning NotImplemented tells Python to attempt reverse addition (50.__radd__(m1)) or raise a clean TypeError.
