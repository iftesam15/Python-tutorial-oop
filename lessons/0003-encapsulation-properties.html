Encapsulation: Closing the Back Door

Your is_valid_amount check only protects callers who go through deposit/withdraw. Nothing stops account.balance = -9999 from bypassing it entirely. Today you close that hole.

The core idea

Python has no true "private" keyword — encapsulation here is mostly convention plus a tool. The convention: a leading underscore, _balance, tells other programmers "this is internal, don't touch it directly" — Python won't stop them, but it's a strong signal. The official docs confirm this is deliberate — Python trusts you.

The tool is @property. It lets a method be accessed like a plain attribute (account.balance, no parentheses), and its partner @balance.setter lets assignment (account.balance = 500) run through your own validation code instead of just overwriting memory. This is the Pythonic version of a getter/setter pair — and it means every path to changing the balance, direct or through a method, is forced through the same gate.

Anatomy: a validated property

class BankAccount:
    bank_name = "Python National Bank"
    account_count = 0

    def __init__(self, owner, balance=0):
        self.owner = owner
        self._balance = 0        # internal storage — leading underscore
        self.balance = balance   # goes through the setter below, validated
        BankAccount.account_count += 1

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("Balance cannot be negative")
        self._balance = value

    def deposit(self, amount):
        self.balance = self.balance + amount   # runs through the setter

    def withdraw(self, amount):
        if amount > self.balance:
            print("Amount exceeds your balance")
            return
        self.balance = self.balance - amount   # runs through the setter


account = BankAccount("Dhrubo", 1000)
account.deposit(500)          # fine — 1500, validated automatically
account.balance = -9999       # raises ValueError — the back door is shut

Notice what didn't change: deposit and withdraw still write to self.balance exactly like before. Because balance is now a property, that assignment is silently routed through balance.setter — every existing caller gets the validation for free, and nobody can bypass it by writing straight to the attribute.

Why the double name
The property is called balance; the real storage is _balance. If the setter were also named balance and tried to do self.balance = value inside itself, it would call the setter again — infinite recursion. The underscore name is what actually holds the data.
