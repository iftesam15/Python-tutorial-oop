Class vs. Instance Attributes, and Two New Decorators

Yesterday every account kept its own private data. Today: data that's shared by every account, and two ways to write methods that aren't about one specific instance at all.

The core idea

An instance attribute (what you built yesterday — self.owner, self.balance) belongs to one object. A class attribute is defined directly in the class body, not inside __init__, and is shared by every instance unless a particular instance overrides it. Think of it as data that describes the category, not any one member of it — every BankAccount is issued by the same bank, so "bank name" belongs on the class, not on each account.

The classic gotcha
self.account_count += 1 inside a method does not update the shared class attribute — it silently creates a brand-new instance attribute that shadows it. To actually mutate shared state, write BankAccount.account_count += 1 (or type(self).account_count += 1), referring to the class explicitly. This trips up almost everyone the first time.

Anatomy: class attributes and two new decorators

class BankAccount:
    bank_name = "Python National Bank"   # class attribute — shared by all
    account_count = 0                    # class attribute — shared by all

    def __init__(self, owner, balance=0):
        self.owner = owner               # instance attribute — per object
        self.balance = balance
        BankAccount.account_count += 1   # mutate the SHARED value

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        if amount > self.balance:
            print("Amount exceeds your balance")
            return
        self.balance -= amount

    @classmethod
    def from_string(cls, data_string):
        """Alternate constructor: build an account from "owner,balance"."""
        owner, balance = data_string.split(",")
        return cls(owner, float(balance))

    @staticmethod
    def is_valid_amount(amount):
        """Doesn't need self or cls — just a related utility check."""
        return amount > 0


account_a = BankAccount("Dhrubo", 1000)
account_c = BankAccount.from_string("Jack,2000")

print(BankAccount.account_count)   # 2 — shared, not per-instance
print(account_a.bank_name)         # "Python National Bank" — same on every account

Two new decorators, two different jobs:

  • @classmethod receives cls (the class) instead of self (an instance). The most common use is an alternate constructor — a second way to build an object, here from a raw string instead of separate arguments.
  • @staticmethod receives neither self nor cls. It's just a regular function that happens to live inside the class because it's conceptually related — here, checking whether an amount is even valid before you try to deposit or withdraw it.
